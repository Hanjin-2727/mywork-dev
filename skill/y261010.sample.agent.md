# 📋 [Template] Antigravity 표준 프로젝트 공통 규칙 정의서 (AGENTS.md 샘플)
**파일명: `y261010.sample.agent.md`**  
**작성일시: 2026-10-10**  
**용도: 새 프로젝트 생성 시 `.agents/AGENTS.md` 또는 `~/.gemini/config/AGENTS.md`로 복사하여 사용하는 표준 템플릿**

---

> [!NOTE]
> **사용 가이드**
> - **프로젝트 적용**: 프로젝트 루트 디렉토리에 `.agents/` 폴더를 생성하고, 본 문서의 `[AGENTS.md 본문 내용]`을 복사하여 `.agents/AGENTS.md`로 저장합니다.
> - **글로벌 적용**: 모든 프로젝트에 전역으로 적용하려면 `~/.gemini/config/AGENTS.md`에 저장합니다.
> - **적용 효과**: Antigravity 3종(CLI, IDE, 2.0 Desktop) 어디서 작업하든 에이전트가 이 규칙을 자동으로 로드하여 일관된 표준을 준수합니다.

---

```markdown
# 🏛️ 프로젝트 에이전트 공통 규칙 (AGENTS.md)

## 1. 프로젝트 기본 원칙 및 형상 관리
- **Single Source of Truth**: 모든 기술 문서와 소스 코드는 GitHub를 단일 진실 공급원(SSOT)으로 관리한다.
- **Local-First & Cloud-Sync**: 
  - 개발 및 에이전트 작업은 로컬 디스크에서 수행하여 랙과 파일 충돌을 방지한다.
  - 작업 시작/종료 및 중요 마일스톤 시점에 원격 저장소(Git / Cloud)와 동기화한다.
- **Docs-as-Code**: 기획 및 설계 문서(PRD, 다이어그램, ERD, WBS)는 코드와 동일하게 `docs/` 디렉토리 내 마크다운(`.md`)으로 관리하며, 코드 변경 시 문서도 같은 커밋에서 함께 갱신한다.

---

## 2. 표준 프로젝트 디렉토리 구조
```text
<project-root>/
├── .agents/
│   └── AGENTS.md               # [필수] 프로젝트 공통 규칙 및 가이드라인
├── inputs/                     # 원본 참고 자료 (RFP, 회의록, 기획안, 엑셀, PDF 등)
├── docs/                       # 기술 기획 및 아키텍처 산출물 (Docs-as-Code)
│   ├── PRD.md                  # 제품 요구사항 정의서
│   ├── sequence_diagram.md     # 시퀀스 다이어그램
│   ├── erd.md                  # 데이터 모델링 (ERD & DDL)
│   └── wbs.md                  # 작업 분할 및 일정 계획표
└── src/                        # 실제 개발 소스 코드
```

---

## 3. 문서화 및 다이어그램 규칙 (Two-Track 정책)

1. **기본 다이어그램 (Mermaid)**:
   - 모든 시퀀스 다이어그램, 아키텍처 흐름도, ERD는 마크다운 파일 내 `mermaid` 코드 블록으로 작성한다.
   - GitHub, IDE, 웹 뷰어에서 추가 설치 없이 즉시 렌더링(Zero-Setup)되는 것을 원칙으로 한다.

2. **발표/보고용 고화질 다이어그램 (D2 / d2lang)**:
   - 경영진 보고, 고객사 제출, 외부 발표 등 고품질 가시성이 요구될 경우 D2 문법으로 작성한다.
   - D2 소스는 `docs/diagrams/*.d2`에 저장하고, D2 CLI로 SVG 벡터 이미지를 생성하여 마크다운에 삽입한다.

---

## 4. 기획 및 개발 산출물 작성 절차 (표준 파이프라인)

에이전트는 새로운 기능 개발 또는 기획 요청 시 다음 순서를 준수하여 산출물을 작성한다:
1. **[1단계] PRD 작성 (`docs/PRD.md`)**
   - 개발 배경 및 목적, 타겟 사용자, 핵심 유저 스토리, 기능/비기능 요구사항, 제외 범위(Out of Scope) 정의.
2. **[2단계] Sequence Diagram 설계 (`docs/sequence_diagram.md`)**
   - 사용자 ↔ 프론트 ↔ 백엔드 ↔ 외부 시스템 간 주요 데이터 및 제어 흐름 시각화.
3. **[3단계] ER Diagram & DB 설계 (`docs/erd.md`)**
   - 엔티티 관계도(Mermaid ERD) 및 테이블 DDL(SQL) 초안 정의.
4. **[4단계] WBS 수립 (`docs/wbs.md`)**
   - 마일스톤별 작업 단위(Work Package), 우선순위, 의존성, 예상 공수 및 Mermaid Gantt 차트 포함.
5. **[5단계] 소스 코드 구현 (`src/`)**
   - `docs/`의 명세를 바탕으로 테스트 코드 작성 후 기능 구현.

---

## 5. 코딩 및 품질 표준
- **언어 및 주석**: 모든 코드 주석, 커밋 메시지, 기획 문서는 한국어를 표준으로 작성한다.
- **보안 원칙**: API 키, 비밀번호, 인증 토큰은 절대 소스 코드에 하드코딩하지 않으며 `.env` 파일로 분리하고 `.gitignore`에 등록한다.
- **예외 처리 & 로깅**: 프로덕션 안정성을 고려하여 주요 비즈니스 로직에는 적절한 예외 처리와 구조화된 로깅을 포함한다.
- **테스트 주도**: 핵심 로직 작성 시 해당 기능을 검증할 수 있는 단위 테스트(Unit Test)를 함께 작성한다.

---

## 6. 에이전트 소통 및 행동 지침
- 작업 전 모호한 요구사항이나 중요한 아키텍처 결정 사항이 있을 경우, 임의로 단정하지 않고 명확한 옵션을 제시하여 확인을 받는다.
- 파일 수정 시 무관한 기존 주석이나 코드를 임의로 삭제하지 않는다.
- 작업 완료 후 변경 내용과 검증 결과를 간결하고 명확하게 요약하여 보고한다.

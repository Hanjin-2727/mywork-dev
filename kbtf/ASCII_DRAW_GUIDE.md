## 1. 기본 구성 요소

### (1) 박스 (Box) 스타일

```text
[1. 초간단 괄호형]
[ 클라이언트 ]   ( 데이터베이스 )   { 모듈 A }   < 판단 조건 >

[2. 표준 ASCII 박스]
+-----------------+
|   서비스 서버   |
+-----------------+

[3. 유니코드 얇은 선 (깔끔함)]
┌─────────────────┐
│   FastAPI 서버  │
└─────────────────┘

[4. 유니코드 둥근 모서리]
╭─────────────────╮
│  Redis 캐시 서버 │
╰─────────────────╯

[5. 유니코드 굵은/이중선 (강조)]
╔═════════════════╗
║  메인 게이트웨이 ║
╚═════════════════╝
```

### (2) 화살표 및 연결선 (Arrows & Connectors)

```text
가로 방향:
  단방향:   ----->    또는   ───►    또는   =====>
  양방향:   <---->    또는   ◄──►    또는   <=====>
  점선:     - - ->    또는   · · · >

세로 방향:
    |             │             ║             :
    |             │             ║             :
    v             ▼             ▼             v

분기 및 모서리:
  +---> (우측 분기)      ┌───► (유니코드)
  |                      │
  +--->                  ├───►
  |                      │
  +                      └
```

## 2. 가장 많이 사용되는 실전 패턴 7선

### 패턴 1: 시스템 아키텍처 (기본)
가장 흔히 쓰이는 웹/앱 클라우드 서비스 구조입니다.

```text
[ 브라우저 / 모바일 앱 ]
          |
          | HTTPS (JSON)
          v
+-----------------------+
|  API Gateway (Nginx)  |
+-----------------------+
          |
          +-----------------------+
          |                       |
          v                       v
+-------------------+   +-------------------+
|  인증/유저 서비스 |   |  핵심 비즈니스 로직|
+-------------------+   +-------------------+
          |                       |
          |       +---------------+---------------+
          |       |                               |
          v       v                               v
    [( PostgreSQL )]                        [ (Redis Cache) ]
```

---

### 패턴 2: 플로우차트 / 조건 분기
로직 흐름과 If-Else 조건문을 표현할 때 사용합니다.

```text
         [ 시작: 로그인 시도 ]
                   |
                   v
          /-----------------\
         <   ID/PW 일치?    >
          \-----------------/
             /           \
     [Yes]  /             \  [No]
           v               v
  +---------------+   +-------------------+
  | JWT 토큰 발급  |   | 실패 횟수 증가     |
  +---------------+   +-------------------+
          |                    |
          |           /-----------------\
          |          <  5회 이상 실패?   >
          |           \-----------------/
          |              /           \
          |      [Yes]  /             \  [No]
          |            v               v
          |     +------------+   +------------+
          |     | 계정 잠금  |   | 재시도 유도|
          |     +------------+   +------------+
          |            |               |
          +------------+---------------+
                       |
                       v
                 [ 종료 / 반환 ]
```

---

### 패턴 3: 시퀀스 다이어그램 (시간순 호출)
클라이언트와 여러 서버 간의 호출 순서를 표현합니다.

```text
[사용자]             [API 서버]             [결제 PG사]             [DB]
   |                     |                     |                    |
   |--- 1. 결제 요청 --->|                     |                    |
   |                     |--- 2. 토큰 검증 ------------------------>|
   |                     |<-- 3. 검증 완료 -------------------------|
   |                     |                     |                    |
   |                     |--- 4. 승인 요청 --->|                    |
   |                     |<-- 5. 결제 성공 ----|                    |
   |                     |                                          |
   |                     |--- 6. 주문 저장 ------------------------>|
   |                     |<-- 7. 저장 완료 -------------------------|
   |<-- 8. 최종 완료 ----|                     |                    |
   |                     |                     |                    |
```

### 패턴 4: 레이어드 (계층형) 아키텍처
소프트웨어 내부 모듈이나 스택 구조를 표현합니다.

```text
+-------------------------------------------------------------+
|               프레젠테이션 계층 (React / PWA UI)             |
+-------------------------------------------------------------+
                              |
+-------------------------------------------------------------+
|              API 라우터 & 컨트롤러 (FastAPI / Router)         |
+-------------------------------------------------------------+
                              |
+-------------------------------------------------------------+
|              도메인 비즈니스 서비스 (Service Layer)          |
+-------------------------------------------------------------+
                              |
+-------------------------------------------------------------+
|             데이터 접근 계층 (Repository / SQLAlchemy)       |
+-------------------------------------------------------------+
                              |
+-------------------------------------------------------------+
|             인프라 & 영속성 계층 (PostgreSQL / Redis)        |
+-------------------------------------------------------------+
```

### 패턴 5: 트리 / 디렉토리 구조
프로젝트 폴더 구성이나 데이터 계층 트리를 표현합니다.

```text
my-project/
├── backend/
│   ├── app/
│   │   ├── api/          # 엔드포인트 라우터
│   │   ├── core/         # 환경설정 및 보안
│   │   ├── models/       # DB 모델 (SQLAlchemy)
│   │   └── services/     # 비즈니스 로직
│   ├── tests/            # 단위/통합 테스트
│   └── Dockerfile
├── frontend/
│   ├── src/
│   │   ├── components/   # 재사용 UI 컴포넌트
│   │   └── pages/        # 라우트 페이지
│   └── package.json
└── README.md
```

### 패턴 6: 데이터베이스 테이블 (ERD)
테이블 스키마와 외래키(FK) 관계를 표현합니다.

```text
+---------------------+              +-----------------------+
|        users        |              |        orders         |
+---------------------+              +-----------------------+
| PK | id   (INT)     |<---+         | PK | id      (INT)    |
|    | email(VARCHAR) |    +---------| FK | user_id (INT)    |
|    | name (VARCHAR) |              |    | amount  (DECIMAL)|
|    | created_at(TS) |              |    | status  (VARCHAR)|
+---------------------+              +-----------------------+
                                                 |
                                                 v 1:N
                                     +-----------------------+
                                     |      order_items      |
                                     +-----------------------+
                                     | PK | id         (INT) |
                                     | FK | order_id   (INT) |
                                     |    | product_name     |
                                     |    | quantity   (INT) |
                                     +-----------------------+
```

           |                         |                         |
           v                         v                         v
     Quality Gate 1            Quality Gate 2            Quality Gate 3

## 3. 복사해서 바로 쓰는 템플릿 모음

### (A) 3단 가로 파이프라인
```text
+---------+       +---------+       +---------+
| STEP 1  | ----> | STEP 2  | ----> | STEP 3  |
+---------+       +---------+       +---------+
```

### (B) 1:N 분기 처리
```text
                  +------------+
            +---> |   Worker 1 |
            |     +------------+
+-------+   |     +------------+
| Queue | --+---> |   Worker 2 |
+-------+   |     +------------+
            |     +------------+
            +---> |   Worker 3 |
                  +------------+
```

### (C) 양방향 핸드셰이크
```text
Client                       Server
  |                            |
  | -------- SYN ------------> |
  | <------- SYN-ACK --------- |
  | -------- ACK ------------> |
  |                            |
```

## 4. AI 에이전트 전달 꿀팁

1. **완벽하게 각 맞출 필요 없습니다**:
   줄이 조금 삐뚤빼뚤하거나 오타가 있어도 괜찮습니다. `[A] -> [B] -> [C]` 식의 핵심 흐름과 명칭만 명확하면 에이전트가 완벽하게 교정합니다.
2. **원하는 결과물 명시하기**:
   - `"이 ASCII 다이어그램 기반으로 예쁜 Mermaid 코드 짜줘"`
   - `"이 구조대로 FastAPI 백엔드 보일러플레이트 코드 작성해줘"`
   - `"이 화면 플로우대로 Tailwind CSS 적용된 React 컴포넌트 만들어줘"`
3. **터미널에 바로 붙여넣기**:
   ASCII는 순수 텍스트이므로 `Ctrl+Shift+V`로 프롬프트에 바로 붙여넣으시면 됩니다.

## 5. 추천 ASCII Draw 도구
* **웹 도구 (무료/브라우저)**:
  - [ASCIIFlow](https://asciiflow.com/) : 마우스로 네모/선을 그리면 ASCII 텍스트로 즉시 변환
  - [Textik](https://textik.com/) : 가볍고 빠른 ASCII 다이어그램 에디터
  - [Diagon](https://arthursonzogni.com/Diagon/) : 마크다운 문법을 ASCII 다이어그램으로 자동 변환
* **VS Code 확장**:
  - `ASCII Tree Generator`, `Text Art`
